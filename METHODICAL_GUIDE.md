## Результат занятия

## Подготовка преподавателя

- JDK 17 и IntelliJ IDEA установлены;
- доступ в интернет для первого Maven Sync есть;
- терминал открыт в папке проекта;
- проверено, что порт 8080 свободен либо известен процесс, который его занимает;
- до показа эталонного решения ученица работает в собственной копии/чистом проекте.

Важно: **сначала ученица делает попытку самостоятельно**. Эталонный код и готовые ответы ниже открывайте только после её устного прогноза или фактической попытки. Цель занятия — не перепечатать решение, а увидеть связь «аннотация → маршрут → HTTP-ответ → тест».

## Пошаговое создание

### 1. Проверить стартовую точку

Попросите ученицу найти `pom.xml`, назвать Java 17 и зависимость `spring-boot-starter-web`. Объяснение: starter приносит Spring MVC и встроенный веб-сервер. Затем найдите класс с `main` и `@SpringBootApplication`.

Вопрос до действия: «Если класс контроллера будет в пакете, не вложенном в пакет приложения, найдёт ли его Spring автоматически?» Ожидаемая гипотеза: нет, стандартное сканирование начинается от пакета основного класса вниз.

### 2. Создать класс контроллера

Пусть ученица в пакете `com.example.controllerendpoints` создаст публичный `PageController`, поставит на класс `@Controller` и `@ResponseBody`, а затем добавит публичный метод `index()` без параметров и возвращаемую строку. После этого попросите добавить путь `/index` через `@GetMapping`.

### 3. Проверить один маршрут

Запустить `ControllerEndpointsApplication` в IntelliJ. Перейти на `http://localhost:8080/index`. Если вместо текста 404, не называйте решение сразу: предложите проверить пакет, `@Controller`, точность `@GetMapping` и перезапуск.

### 4. Добавить второй маршрут

Ученица по аналогии реализует `/contact`, но вводит текст самостоятельно. Затем сравнивает обе фразы с контрактом посимвольно. Подчеркните: повтор кода здесь допустим как учебный пример; преждевременная абстракция не нужна.

### 5. Разобрать тесты

Откройте `PageControllerTest`. Попросите расшифровать строку:

```java
mockMvc.perform(get("/index"))
       .andExpect(status().isOk())
       .andExpect(content().string("This is the main page"));
```

Затем пусть ученица предскажет исход теста для `/unknown`, а после — запустит `./mvnw test` или тест из IntelliJ. `contextLoads()` рассматривайте отдельно: это проверка запуска контекста, а не детальная проверка URL.

## Эталон — открыть только после самостоятельной попытки

Предупредите: ниже находится готовая форма, поэтому сначала нужно написать свой вариант и объяснить его.

```java
@Controller
@ResponseBody
public class PageController {

    @GetMapping("/index")
    public String index() {
        return "This is the main page";
    }

    @GetMapping("/contact")
    public String contact() {
        return "This is the contact page";
    }
}
```

Подготовленный ответ на вопрос «почему здесь `@ResponseBody`?» показывайте только после ответа ученицы: «Она стоит на классе, поэтому Spring помещает результаты обоих его методов в HTTP body, а не трактует их как имена view».

## Сценарий защиты

1. «Покажи точку входа и расскажи, что запускается».  
   **Модельный ответ:** `ControllerEndpointsApplication` с `@SpringBootApplication` передаётся в `SpringApplication.run`. Spring создаёт context, находит контроллер и запускает встроенный Tomcat, который принимает HTTP-запросы на порту 8080 по умолчанию.
2. «Открой `PageController`: какой метод обслужит `GET /contact`?»  
   **Модельный ответ:** публичный метод `contact()`, потому что над ним стоит `@GetMapping("/contact")`. Он возвращает точную строку `This is the contact page`.
3. «Почему строка отправляется клиенту, а не ищется HTML-шаблон?»  
   **Модельный ответ:** `@ResponseBody` размещена на публичном классе `PageController` и действует на оба его метода. Поэтому возвращённый `String` становится HTTP body, а не именем шаблона.
4. «Измени один символ в ожидаемом тексте теста: что должно произойти?»  
   **Модельный ответ:** MockMvc-тест должен упасть, поскольку `content().string(...)` сравнивает тело ответа с ожидаемой строкой точно, включая регистр и пробелы.
5. «Почему тест на `/unknown` ожидает 404?»  
   **Модельный ответ:** для `GET /unknown` в контроллере нет `@GetMapping`; Spring MVC не находит обработчик и возвращает `404 Not Found`.
6. «Назови одну ситуацию, когда вместо этого решения понадобился бы Thymeleaf».  
   **Модельный ответ:** Thymeleaf пригодился бы, если сервер должен сформировать HTML-страницу из шаблона и передать в неё данные. В этом проекте он не нужен, так как контракт требует только plain-text строки.

Ожидаемый итог защиты — ученица уверенно объясняет базовый MVC-поток, а не только демонстрирует страницы. Thymeleaf допустимо упомянуть исключительно как неиспользуемую альтернативу для серверных HTML-шаблонов.
